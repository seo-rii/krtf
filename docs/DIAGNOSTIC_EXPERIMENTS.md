# 원문·pack 영향과 의미 안전성 후속 실험

[앞선 5,568회 실험](../reports/extended_queue_20261019/RESULTS.md)은 두 모델 모두
오류·누락 없이 완료됐다. 입력 상한 1,024 tokens에서 정답 존재 문항의 정답 수는
Gemma 44→36/64, Qwen 48→41/64로 감소했다. 합성 안전성 96건의 잘못된 ID
승인은 Gemma 10건, Qwen 0건이었다. 이 결과를 보고 아래 진단을 추가했다.

| 트랙 | 모델별 요청 | 확인할 질문 |
|---|---:|---|
| `source_pack_factorial` | 128 ×6 =768 | 성능 손실이 원문 축소, pack 내용, 부가 정보 중 어디에서 생기는가? |
| `fresh_compact` | 128 ×3 =384 | 간결한 pack의 효과가 미사용 문맥에서도 나타나는가? |
| `safety_robustness` | (기존 96 + 신규 64) ×4 =640 | prompt 순서와 명시적 문맥 확인 지시에 따라 잘못된 ID 승인이 달라지는가? |

Gemma 12B 세 트랙 → Qwen 27B 세 트랙, 총 **3,584회**다. 기존 모델·tokenizer,
temperature 0, seed 0, thinking off, strict JSON, 출력 상한 128 tokens,
조건별 1회, 재시도 없음은 유지한다. 모델 비교는 계열과 크기가 함께 바뀐다.

## 원문량 × pack 표현

기존 `budget`의 128문항과 정답을 봉인 입력에서 그대로 가져온다. 원문은
`cap1536_bm25`의 window와 `cap1024_bm25_pack`의 축소된 window 두 수준이며,
각각 pack 없음·간결한 pack·전체 pack을 교차한다. 질문별 pack 사실은 전체
원문에서 한 번 준비해 고정한다. 원문 축소 후 후보를 다시 선정하지 않는다.

여섯 조건의 system 정책은 동일하다. 간결한 표현은 canonical·정의·관측
표현·분해 및 모호성 정보와 의미상 주의사항을 보존하며 부가 metadata를 줄인다.
따라서 이 비교는 문자열 직렬화만의 차이가 아니고, 생산 기본 설정의
동일 토큰 상한 비교도 아니다. 실제 전체 입력 토큰과 원문 내 정답 보존을
함께 보고하고, 원문량별 pack 효과와 pack별 원문 축소 효과를 비교한다.

기존 결과를 본 질문을 재사용하므로 원인 분석용이다. 질문 수나 효과 크기를
독립적인 새 검증 결과로 합산하지 않는다. 검색·정답률·pack 주입 여부로
실패 문항을 제거하지 않는다.

## 새 문맥에서 pack 없음·전체·간결한 표현 비교

같은 고정 KLUE-MRC validation 원본에서 SPAN 64건·NO_ANSWER 64건을
출력 생성 전에 결정한다. 앞선 256문맥과 **검색에 사용했던 512문맥 전체**를
제외한다. 검색 결과로 반환되지 않았던 distractor도 포함해 이전 코퍼스를
재구성하고 봉인 hash와 대조한다. 이전 TyDiQA·KLUE-NER·blind 자료에 대한
정규화 exact·문장·5-gram 중복 제외도 유지한다.

BM25 근거 window는 세 조건에서 동일하며 최대 3개, 3,000자, 두 tokenizer
각 source 1,536 tokens 상한을 적용한다. 전체/간결한 pack은 같은 사실과
보수 정책을 사용하고, `should_inject=false`를 존중한다. pack 없음은 기존 QA
근거 정책을 사용하므로 이 트랙의 no-pack 대비는 pack과 그 정책의 합성 효과다.

이 표본은 새 외부 코퍼스가 아닌 같은 코퍼스의 미사용 문맥 검증이다. 원래
기사 ID가 없어 context hash를 사용하며 기사 독립성이나 사전학습 미노출을
보장하지 않는다. 데이터 부족 시 기존 제외 기준을 느슨하게 하지 않고 중단한다.

## 의미 안전성의 prompt 의존성

기존 24 family·96건은 `exposed_diagnostic`, 새 가상 이름을 사용하는
16 family·64건은 `fresh_family`로 구분한다. 신규 자료는 동명 지명·기관/역할·
과거/현재 조직·모호성/비언급 네 유형이며 family마다 LINK 2건과 비LINK 2건이다.
AI 작성·별도 AI 정답 검토를 resolver 실행 전에 끝낸다. 신규 이름의 family
검증이지만 문장 구조가 유사하므로 광범위한 실제 문서 일반화로 해석하지 않는다.

동일한 원문·대상 span·pack을 사용해 pack 위치(문서 앞/뒤)와 지시문
(기존 지시/명시적 의미 확인)을 교차한다. 추가 지시는 국가·시간·대상 유형·
전체 표현의 의미와 정의가 충돌하거나 불명확하면 기권하도록 한다. 사례별
정답·오류 여부를 지시문에 넣지 않는다. 추가 실행 권한을 부여하지 않으며
모델의 전체 parsed response를 기존 production execution guard에 전달한다.

split별 올바른 ID 승인·잘못된 ID 승인·오답 차단·올바른 기권·과잉 기권과
조건 사이 유익한/해로운 전환을 보고한다. 기존·신규를 합친 값은 처리량
요약일 뿐 독립 검증 점수가 아니다. family와 조건을 독립 표본으로 세지 않는다.
이번 결과로 임계값을 고르거나 배포 오류율 보장을 주장하지 않는다.

## 실행·공개

봉인 소스와 이전 요청 hash 검증, 전체 테스트, 실제 두 tokenizer/chat template,
vLLM IPC bind를 통과한 뒤 one-server에서 직렬 실행한다. 원문·개별 정답·응답은
비공개 보관한다. 원시 응답 재파싱·재채점이 원격 집계와 일치한 경우에만
집계·설정·hash를 커밋하고 푸시한다. 생산 resolver나 guard는 수정하지 않는다.

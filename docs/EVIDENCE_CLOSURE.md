# 근거 연결·기권 분기와 균형·긴 문서 비교

2026-10-23. [직전 새 자료 확인](../reports/support_final_queue_20261022/RESULTS.md)에서
정상48건의 shadow 판정은 Gemma24건, Qwen31건이었다. 요청 발생 위치가 근거에
포함되지 않아 거절된 결과16/14건과 속성이 선택 문단 밖에 있어 거절된 결과6/2건을
관찰했다. 이 횟수는 겹칠 수 있으며 자동으로 더해 회복 건수로 해석하지 않는다.

## 가설과 다섯 조건

| 조건 | 서버 근거 연결 | 기권 분기 | 양성 근거 출력 |
|---|---|---|---|
| `manual_legacy` | 모델이 모든 문단 선택 | 기존 다섯 필드 | 개별 문단·속성 참조 |
| `closure_legacy` | 대상·선택 속성의 부모 문단 추가 | 기존 다섯 필드 | 개별 문단·속성 참조 |
| `manual_null` | 모델이 모든 문단 선택 | null 전용 두 필드 | 개별 문단·속성 참조 |
| `closure_null` | 대상·선택 속성의 부모 문단 추가 | null 전용 두 필드 | 개별 문단·속성 참조 |
| `closure_bundle` | 요청에 묶인 근거 묶음 복원 | null 전용 두 필드 | 서버의 묶음 참조 |

앞 네 조건은 서버 연결×기권 형식의2×2비교다. 묶음 조건은 개선된 방식에서 출력
비용을 더 줄일 수 있는지 비교한다. 모든 조건에 같은 전체 원문·실제 후보·정의·
적용 범위와 묶음 목록을 제공한다. 참조는 조건마다 요청·문서·snapshot·발생 위치에
묶는다. 응답 형식에 따른 정책 문구 변화도 개입에 포함한다.

서버 연결은 요청한 발생 위치의 원문과 **모델이 이미 선택한 속성**의 부모 문단만
더한다. entity·속성·SUPPORT 판단을 새로 만들지 않고, 잘못된 참조·다른 대상의
근거를 지워 오류를 숨기지 않는다. 기존 소유 귀속·명시적 모순·전체 표현 의미
검사를 유지한다. 기권 전용 분기는 `{r,e:null}`만 허용하고, 양성 분기는 필요한
모든 필드를 요구한다. 잘못된 추가 필드를 묵인하지 않는다.

묶음은 원문과 후보 메타데이터만으로 제한된 조합을 만든다. 누락 속성을 보충하거나
사전 정의를 원문 근거로 취급하지 않는다. 생성·생략 수를 보고하며 묶음 선택 뒤에도
동일한 근거 검사와 출처 귀속 검사를 적용한다.

## CPU 진단과 새 자료

기존96문서의 봉인된 원시 응답으로 원본, 서버 연결, 기권 투영, 두 변환 결합을
재분석한다. CPU 재분석에서 근거 연결 후 정상 shadow 판정은 Gemma24→45/48, Qwen31→47/48이며
추가 오판정은0건이다. 기권 투영 후 정상 기권은31→47건,35→46건이다. 이는
아래 새 자료의 성능이나 독립적인 안전 검증으로 합산하지 않는다.

원시 응답·기존 성적은 변경하지 않는다. 특히 null 투영은 기존 null
제안에서 추가 필드를 생략했다면 어땠는지 보는 사후 가정이며, 새로운 모델 성능이나
운영 검증의 통과로 표시하지 않는다.

새 최종 자료는96문서·12개 용어군,48짧은 문서와48긴 문서다. 국내/해외와 절차/
시스템을 A/B에 균형 있게 배치하고, 문맥으로 구분되는 공유 약칭의 정답도 A/B를
균등하게 둔다. 긴 문서는 반복 표기·다른 등록 대상·인용·정정을 섞어 출처 귀속을
점검한다. 문서 전체와 정의를 자르지 않는다.

자료와 정답·core/full span·지원 근거는 resolver·모델 출력 전에 AI가 작성하고
다른 검토자가 확인한 뒤 해시로 봉인한다. 자료는 여전히 AI 합성이며, 구조화된
시나리오의 상관과 저자 편향이 남는다. 사람 gold·실제 업무 분포·배포 오류율을
대표하지 않는다. 긴 문서의 오류는 짧은 문서와 나눠 보고한다.

## 실행과 해석

모델별96×5=480회, Gemma12B→Qwen27B로 총 **960회**다. temperature0,seed0,
thinking off,strict JSON,출력 상한768tokens,재시도 없는 단일 생성이다. 전체
테스트와 두 실제 tokenizer의8192-token 한도, vLLM의 분기 schema 컴파일과 IPC
검사를 통과한 뒤 실행한다. 넘치는 입력은 잘라 맞추지 않고 준비 단계에서 실패한다.

제안의 정오와 raw 검사·서버 연결 후 검사, 실제 production guard 결과, 실험용
shadow 판정을 분리한다. 서버가 더한 문단 수, null 분기 오류, 정상 판정·오판정·
기권·과잉 보류, 길이별·용어군별 변화와 입력/출력 token,p50/p95/p99 지연을 남긴다.
원문·문서·용어군을 보존한 paired 비교를 사용하며 호출 수를 독립 표본 수로 세지 않는다.

모든 결과는 실행 권한 없는 shadow 실험이다. 운영 승인 계약과 실제 업무 상태를
변경하지 않는다. one-server의 다른 GPU 프로세스를 중지하지 않고 자원을 기다린다.
비공개 원시 응답을 봉인된 코드로 재채점한 집계만 게시한다. 실제 업무 shadow는
문서·용어집 입력 전까지 `WAITING_FOR_INPUT`이다.

## 완료 결과

960회 생성·재채점·결과 게시가 완료됐다. Gemma는 최초 KV 캐시 기동 실패 후
메모리 예약만 0.45→0.75로 높여 480회를 실행했고, Qwen의 완료된 480회는 원본
응답·환경·해시를 보존해 재사용했다. 복구 코드 전체 테스트는 2,495개 통과,
11개 건너뜀이다. [최종 분석](../reports/closure_recovery_20261023/ANALYSIS.md).

Qwen의 `closure_bundle`은 정상 shadow 연결 46/48건, 오승인 0건, 음성의 유효
기권 48/48건이었다. `closure_null`의 정상 연결 수를 유지하면서 p95는
15.10→7.04초, 출력 토큰은 47.9% 감소했다. 전체 토큰 감소는 0.72%다.

Gemma는 `closure_legacy`에서 정상 연결 31/48건이었지만, 새 null 분기 세 조건은
모두 정상 연결 0건이었다. 양성에서 과도한 기권과 출력 상한에 도달한 형식 오류
44건이 발생했다. 모델별 실제 생성 호환성 확인 없이 이 형식을 공통 설정으로
적용할 수 없다.

두 모델의 모든 조건에서 서버가 추가한 segment는 0건이고 raw/closed 판정도
같았다. 관측된 개선은 정책 문구·출력 형식의 효과를 포함하며, 실제 서버 근거
보충의 효과는 이번 자료에서 입증되지 않았다. 실험용 shadow 판정과 생산 guard
판정을 구분하고, AI 합성 자료의 결과를 운영 오류 보장으로 해석하지 않는다.

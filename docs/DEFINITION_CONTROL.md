# Definition formatting and contextual authorization controls

This follow-up separates exact answer extraction from a bounded definition
normalization diagnostic. Original document-context results remain sealed and
unchanged. The diagnostic permits only whitespace, one Korean copula and one
terminal period around the complete definition. Extra assertions, paraphrases,
multiple definitions and contradictions remain review cases; substring presence
alone is insufficient. AI review of these cases is recorded separately from
scores and does not constitute human verification.

Each new inference receives the complete source, the same explicit target span
and one of six declared conditions:

| Condition | Candidate information | Routing contract |
|---|---|---|
| prose_all | Every catalog entry, exact definition boundaries in prose | Provided-ID membership proposal |
| cards_all | The same entries and facts as JSON cards | Provided-ID membership proposal |
| cards_retrieved | Cards selected from lexical knowledge paragraph windows | Provided-ID membership proposal |
| ktrf_qa_cards | Cards actually exposed by the QA pack, neutral policy | Provided-ID membership proposal |
| ktrf_execution_cards | Original task-specific production QA/automation pack | Production execution guard for routing |
| ktrf_contextual_execution_cards | The same production path with experimental literal definition evidence | Production execution guard for routing |

Only prose_all versus cards_all isolates presentation. Both show the exact
registered definition and explicitly ask for its value without copula or
explanation. Other comparisons measure candidate exposure, policy and
execution authorization together. QA and routing have separate calls and
schemas. Report exact output match, bounded normalized QA, UNASSESSED cases,
accepted correct/wrong non-null IDs, candidate availability and actual costs.

The runtime flag `RuntimePolicy.contextual_exact_resolution` defaults to false.
The experimental path recognizes literal direct identity declarations for an
exact alias collision, optionally introduced by a closed set of document/request
locatives. It preserves the complete candidate pool and output
budget invariants, requires valid exact boundaries and SAME full-surface
identity, and cannot bypass structural, scope or overflow blockers. Quotes,
disputed definitions, unsupported role/NIL context and competing registered
anchors prevent promotion. Implicit adjacent or distant antecedents do not
provide execution authorization. Denial checks cover the target paragraph and
its next paragraph; this bounded experiment does not validate every assertion
elsewhere in the document. Unrelated workflow negation is kept distinct from
identity denial. Short canonical names below the anchor minimum remain unsupported. Fitted fusion/calibration artifacts are not
used with this untrained evidence feature. The resulting prior is explicitly
heuristic, with evidence offsets/quotes and no valid coverage guarantee.

The study combines the original 32 short colliding-alias documents with 32
newly authored direct-definition and hard-negative documents. Original gold
is fixed; additional documents have new IDs, AI provenance and explicit review.
Neither corpus supplies an independent risk certificate. With six conditions
and two tasks, 64 documents give 768 requests/model, 1,536 total for Gemma 12B
and Qwen 27B. Failure to resolve an original contextual-only case is retained,
not repaired by injecting its gold definition.

Inputs, source archive, protocol and inference are frozen before execution.
Actual checkpoint chat templates verify prompt capacity without truncation.
The sequential queue starts one owned runtime at a time and waits for shared
GPU resources. Reports verify manifest seals, artifact hashes, counts and
frozen regrading before collection and push. Historical diagnostics and new
inference reports have separate output directories.

# 리뷰 후속 실험 계약

2026-10-20. 리뷰 기준 `6164ef6`에서 확인한 보정 독립성, 정의 생략 표시,
발생 위치 실행 검증, dense 아티팩트 무결성을 먼저 보강한 뒤 수행한다.
이번 문서는 생성 전 계획이며 완료 결과는 `reports/review_queue_20261020/`에
별도로 게시한다. 기본 resolver의 확정 임계값이나 자동 실행 권한을 늘리지 않는다.

## 실행 행렬

| 트랙 | 표본과 조건 | 모델별 요청 |
|---|---|---:|
| `review_abcd` | 공개 문맥 64 + AI 업무 문서 64 × A/B/C/D × 원문 고정/전체 입력 예산 고정 | 1,024 |
| `review_policy` | 같은 공개 64 × pack 유무 × 근거 전용/용어 QA/문서 QA 정책 | 384 |
| `review_budget` | 같은 공개 64 × 입력 1,024/1,536 tokens × 검색만/pack 우선/원문 우선 | 384 |
| `review_nomiracl` | 한국어 128 × 근거만/용어 QA pack/문서 QA pack | 384 |
| `review_routing` | AI 업무 64 + 공개 표적 32 × selector/의미 확인 지시/동일 사실 통제 | 768 |

Gemma 12B 다섯 트랙 다음에 Qwen 27B 다섯 트랙을 직렬로 실행한다.
총 **5,888회**다. 동일 checkpoint·동일 봉인 입력을 사용하고 temperature 0,
seed 0, thinking off, strict JSON, 조건별 1회·재시도 없음으로 고정한다.
QA 출력 상한은 128 tokens, 발생 위치 식별자를 반환하는 실행 출력은 384 tokens다.
모델 계열과 크기가 함께 바뀌므로 파라미터 수만의 효과로 해석하지 않는다.

별도 실제 후보 실험은 lexical과 KURE-Reranker-nano를 비교한다. 기존 개발/소비된
heldout 552대상과 새 업무 64대상, 총 616대상을 사용한다. 이전 두 cohort는
노출된 원인 분석으로 표시하며, 새 64개도 AI 합성 자료다. 이 pair 점수 호출은
위의 LLM 5,888회와 별개다. 모델 로딩과 전체 pair 토큰 검증 후 원격에서 실행한다.

## 자료와 주석

공개 QA는 고정 KLUE-MRC validation 원본에서 SPAN 32건·NO_ANSWER 32건을
출력 생성 전에 선택했다. 이전 검색 코퍼스 512문맥과 직전 fresh compact
128문맥, 그 전 질문 및 TyDiQA/KLUE-NER/blind 자료와의 선언된 중복을 제외했다.
원문 row ID·context hash·원천 revision·파일 hash·제외 규약을 유지한다.
context hash는 원래 기사 ID나 사전학습 미노출의 증거가 아니다.

공개 표적 32개는 이 64문맥에서 source hash 순서로 먼저 정했다. 각 문맥에서
원문과 사전만 보고 표적 하나를 AI가 주석하고 별도 AI가 검토했다. 등록 기관을
우선하는 표적 선정 규칙이므로 임의 mention의 무작위 감사나 문서 전체 gold가
아니다. 문맥은 그대로 보존했고 10 LINK·21 NIL·1 NON_MENTION이다.

AI 업무 자료는 가상 기업의 16개 용어집 family·64문서다. family마다 LINK 2건과
다른 관할·시점·역할·동명 대상 등 음성 2건이 있다. 원문에 없는 사전 코드/담당
정보를 묻는 질문과 원문 날짜/수량 질문을 포함한다. 용어 해석 필요 여부는
resolver나 모델 출력을 보기 전에 주석했다. 미등록 오타 4건과 같은 표기의
서로 다른 발생도 포함한다. 원문·정의·예외·정답을 먼저 작성하고 독립 AI 검토를
봉인한 뒤 resolver를 실행한다. 검토 중 발견한 지시 대상 해석 이견 1건은
생성 전에 문장을 명확히 고쳤다. AI 작성·AI 검토이며 사람 gold가 아니다.
실제 사내 업무 분포나 사람의 수정 시간은 이 자료로 측정하지 않는다.

네 QA 트랙과 공개 실행 표적은 문맥을 공유한다. 같은 질문의 조건·family·표적을
독립 표본으로 합산하지 않는다. 과거 42개 pack 주입 문항의 재분석은 사후
진단으로만 게시하고 새 모집단을 선택하는 기준으로 사용하지 않는다.

## A/B/C/D와 과제 정책

- A: 검색한 원문만 제공한다.
- B: 동일 원문과 같은 활성 사전에서 결정적 lexical 검색으로 고른 평문 용어표.
- C: 강화된 현재 코어가 만드는 pack과 기존 용어 정의 QA 정책.
- D: 문서 QA 정책과 원문 우선 예산, 의미 제한을 보존하는 완결된 fact card 주입.

고정 원문 비교는 검색 window를 일치시킨다. 전체 예산 고정 비교는 system·질문·
원문·용어표/pack·실제 chat template 입력을 모두 1,536 tokens 이내로 맞춘다.
실제 소비 토큰이 같다는 뜻은 아니며 출력 상한은 별도로 모델 용량에 예약한다.
B−A는 정보 제공, C−B는 전체 pipeline, D−C는 개선 구성을 비교한다. 정책과
선별이 함께 바뀌는 제품 비교이며 독립적인 단일 구성요소 효과로 해석하지 않는다.

공개 MRC는 원문에서 답을 확인하는 과제다. 가상 업무 QA는 제공한 사전 사실도
답변 근거가 될 수 있는 reference-grounded 과제다. 후자는 질문별 정답/필요성
라벨로 정책을 고르지 않고 cohort의 명시적인 과제 계약으로 고정한다.
사전에만 있는 승인 코드를 묻는데 사전 근거 사용을 금지하는 모순을 피한다.
두 과제의 분모와 결과를 별도로 보고한다.

정책 트랙에서는 원문을 고정하고 pack 유무와 세 정책을 교차한다. `should_inject`
판단을 존중하고, 주입하지 않은 경우도 제외하지 않는다. 정책만 붙는 조건도
유지하여 정보와 지시 효과를 나눈다. 예산 트랙은 동일 문서 QA 정책에서 비교한다.
원문 우선 구성은 원문을 먼저 확보하고 남는 공간에 완결된 카드만 넣는다.
카드가 들어가지 않으면 생략/bypass를 기록한다. 원문·정의를 정답 기준으로
자르거나 모델 실패 문항을 표본에서 제외하지 않는다.

## 실행과 의미 확인

실행 트랙의 여덟 조건은 일반 사전 검색/KTRF × 기본/의미 확인 지시를 실제
pipeline에서 비교하고, 동일 사전 사실을 제공하는 네 representation 통제도
병행한다. 후자는 카드 사실을 동일하게 유지하되 실제 resolver 상태를 표시한다.
미확정 후보를 확정 사실로 승격시키거나 모델 선택으로 guard를 우회하지 않는다.

각 모델은 document hash·snapshot ID·mention ID·core/full span·entity ID를 반환한다.
응답 전체를 새 `occurrence_v1` guard에 전달한다. 일반 사전 검색 기준선은 제공된
ID와 요청 발생 위치의 일치를 자체 검사한다. KTRF guard를 일반 검색에 적용해
기준선 점수로 부르지 않는다. 두 조건 모두 요청한 표적과 다른 발생을 선택하면
거부한다. 원시 의미 정답과 실제 승인된 ID 정확도를 별도로 집계한다.

## NoMIRACL과 통계 해석

[공식 NoMIRACL](https://huggingface.co/datasets/miracl/nomiracl)의 한국어 test를
revision `ecd08778d0426a5ca28ac99763b0c9ddc2c78e68`에 고정한다. relevant와
non-relevant에서 각 64건을 선언된 순서와 실제 두 tokenizer 용량으로 선택한다.
질문별 제공 문단 전체를 유지하고, 용량을 넘으면 질문 전체를 제외·기록한다.
정답 문단만 골라 넣거나 문단 제거 뒤 원래 관련성 라벨을 재사용하지 않는다.

과제는 제공 문단에 답의 근거가 있는지 판별하는 것이다. relevant에는 YES,
non-relevant에는 null을 요구한다. 답변 생성 EM·entity ID 정답·전체 코퍼스 NIL과
다른 지표이며 공식 연구의 모든 설정을 재현한 leaderboard 점수도 아니다.
같은 원문 article을 공유하는 질문은 연결 성분으로 관리한다.

조건별 정답·기권·잘못 승인한 ID·문서별 오승인·원문 근거 보존·실제 token과
지연을 보고한다. 문서/family를 보존한 paired bootstrap은 기술적 진단 구간이며,
배포 위험 보장이 아니다. 문자 F1은 순서/관계 방향의 의미 판정을 대신하지 않는다.
독립 무작위 감사 자료가 없으므로 `fixed_risk`의 운영 PASS를 주장하지 않으며,
합성 오류 0건이나 반복 호출 수로 독립 승인 사건 수를 대체하지 않는다.

## 재현·공개

전체 테스트·원천/주석 hash·실제 두 tokenizer·vLLM IPC bind를 먼저 확인한다.
소스 archive, 요청, 설정, raw response를 봉인하고 재파싱·재채점이 일치할 때만
집계 보고서를 푸시한다. 과거 응답 재분석은 원래 frozen source와 명시적 legacy
계약을 사용한다. 새로운 strict 실행 결과와 역사적 surface 승인 점수를 섞지 않는다.
원문·개별 답변은 비공개 보관한다. 공개물은 집계·설정·hash·제약과 실행 증빙이다.

# 근거 묶음·순서·방해 문맥 후속 비교

2026-10-22. [진행 중인 효율화 비교](../reports/EFFICIENCY_PLAN_20261021.md)의
64개 소스를 재사용하는 **후속 진단**이다. 방법은 선행 실행의 응답·점수를 읽지
않고 고정한다. 같은 원문을 다시 쓰므로 새 독립 확인 자료로 세지 않는다.
실제 업무 자료나 사람 gold를 대신하지 않는다.

## 비교 조건

| 조건 | 응답 형식 | 입력 변화 |
|---|---|---|
| `compact_control` | 요청·entity·판단·문단·네 속성 참조 | 원래 순서 |
| `bundle_control` | 요청·entity·판단·근거 묶음 참조 | 원래 순서 |
| `compact_reordered` | 개별 근거 참조 | 후보와 근거 행 순서 뒤집기 |
| `bundle_reordered` | 근거 묶음 참조 | 후보·근거·묶음 행 순서 뒤집기 |
| `compact_distractors` | 개별 근거 참조 | 권한 없는 별도 방해 문맥 추가 |
| `bundle_distractors` | 근거 묶음 참조 | 같은 방해 문맥 추가 |

두 형식에 같은 전체 사실 표와 묶음 목록을 제공한다. 묶음은 요청·entity·원문
문단·네 속성 위치를 서버에서 함께 복원하는 참조다.
모델은 묶음을 선택하며, 선택 후에도 기존 네 속성 일치 검사와 production
occurrence 검증을 모두 통과해야 한다. 묶음을 만들었다는 사실은 승인이 아니다.
다른 entity나 요청의 묶음, 이전 요청의 참조, 잘못된 문서·발생 위치는 사용할 수 없다.
조합 수는 사전 지정한 상한으로 제한하고 생략된 조합 수를 별도 기록한다.

순서 변경은 표시 순서만 바꾼다. 원문, entity 정의·적용 범위, 후보 집합, 근거
좌표와 승인 검증은 유지한다. 방해 문맥은 목표 문서 밖의 비권위 참고문으로
명시하고, 원문의 근거 목록이나 문서 해시에 편입하지 않는다. 따라서 이 조건은
검색 품질 비교가 아니라 추가 문맥에 의해 발생 위치 판단이 흔들리는지 보는
스트레스 시험이다. 방해 문맥이 추가된 조건의 입력 비용도 함께 보고한다.

## 자료·실행 고정

자료는 앞서 AI가 작성·독립 AI 검토한 64문서·8개 family다. 원래 개발 16문서와
확인 48문서의 표시는 **소스의 이전 분할**로만 보존한다. 이 후속 실험 전체의
모집단은 `REUSED_SEALED_SOURCE_DIAGNOSTIC`이며 새 holdout 성능으로 부르지
않는다. 정답·문서·family·event·core/full span을 고치지 않는다.

Gemma 12B와 Qwen 27B에 각 64×6=384회, **총 768회**를 실행한다. 두 모델은
같은 봉인된 요청을 사용한다. temperature 0, seed 0, thinking off, strict JSON,
공통 출력 상한 768 tokens, 재시도 없는 단일 생성이다. 실제 두 tokenizer로
원문·정의·조건을 자르지 않고 8,192-token context 안에 드는지 먼저 검증한다.

선행 640회가 두 모델에서 모두 성공하고, 원시 응답 재채점·집계 푸시까지 끝난
뒤에 이 큐를 시작한다. 선행 실패나 수집 실패는 자동으로 건너뛰지 않는다.
시작 시 선행 큐의 완료 상태와 게시 완료 표식을 다시 검사한다. 다른 GPU
프로세스를 중지하지 않으며 자원이 사용 중이면 기다린다.

## 해석할 지표

의미 제안과 실행 승인을 분리해 올바른/잘못된 ID 제안·승인, 과잉 보류,
schema·참조·근거 거절 사유를 보고한다. 형식별 입력·출력 토큰과 p50/p95/p99
지연, 묶음 수·생략 수, 각 원문에 대한 조건 간 변화도 보존한다. family 단위
paired 비교를 쓰며 768회 호출을 독립 사건 768개로 계산하지 않는다.

`bundle_control−compact_control`은 근거 출력 묶음의 비용·품질 차이다.
각 형식의 `reordered−control`, `distractors−control`은 순서와 추가 문맥의
민감도다. 묶음 조건에서는 응답 형식과 그 사용 지시가 함께 바뀌므로 출력 토큰 수만의
효과로 해석하지 않는다. 근거 일치 검사는 의미 함의나 배포 오류율의 보장이 아니다.

원시 요청·응답은 비공개로 보존한다. 코드·소스·요청·tokenizer·schema를 봉인한
뒤 응답을 재파싱·재채점한 집계만 `reports/robustness_queue_20261022/`에 게시한다.
실제 업무 shadow 평가는 입력이 제공될 때까지 `WAITING_FOR_INPUT`이다.

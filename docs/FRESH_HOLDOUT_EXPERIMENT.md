# 미사용 기사에서의 결합 조건 재검증

[결합 비교](../reports/combined_queue_20261018/RESULTS.md)에서 BM25가 도움이 됐지만,
같은 원문에 KTRF pack을 더한 이득은 관찰되지 않았다. 이미 선택한 네 조건을
앞선 실험과 겹치지 않는 기사에서 확인한다. 운영 기본값은 변경하지 않는다.

## 표본과 사전 제외

고정 TyDiQA 한국어 validation 1,698질문에서 기존 근거 평가 256질문, QA 준비
pool 384질문과 최종 128질문, blind 문단 24개의 기사, 검색·결합 비교 128질문의
parent ID 및 본문 SHA-256을 모두 제외한다. 제외 입력 자체의 해시도 고정한다.
제외 집합은 504 parent ID·529 해시이며 1,415질문이 제외된다. 남은 283질문 중
유효한 양성은 SPAN 7질문/6기사, YES/NO 12질문/12기사뿐이다.

새 양성 기사를 모두 포함하는 **SPAN 6·YES/NO 12·무응답 18 = 36질문/36기사**를
생성 전에 선언한다. 원래 고정 seed의 ID 해시 순서를 사용하고 기사·본문 해시당
질문 하나를 선택한다. 양성 18개는 높은 검정력이나 운영 위험 보장을 주지 않는다.
YES/NO가 양성의 2/3이므로 SPAN·YES/NO 성능을 반드시 따로 보고한다.

문항 선택에는 정답 유형 외에 검색 성공 여부, 정답 문단의 길이, pack 주입 여부,
모델 답변을 사용하지 않는다. 선택된 문항이 실제 토큰 예산을 넘으면 준비를 실패
처리하며 문항을 조용히 교체하지 않는다. 문서 집합 검색과 새 코퍼스 일반화 시험은
아니며, 근접 중복·다른 자료와의 중복·사전학습 노출까지 배제하지 않는다.

## 고정 비교와 평가

| 조건 | 원문 선택 | KTRF | 생성 |
|---|---|---|---|
| lexical | 기존 어휘 검색 | 없음 | strict JSON Schema |
| lexical_pack | 동일 lexical 구간 | `should_inject`일 때만 주입 | 동일 |
| bm25 | 기존 BM25, k1=1.2·b=0.75 | 없음 | 동일 |
| bm25_pack | 동일 BM25 구간 | 해당 질문·구간에서 재구성 | 동일 |

기존 170-entity 사전·`commit`·`qa_grounding`·pack 예산 800을 유지한다. 원문
1,536토큰/3,000문자/3구간 상한, 온도 0·seed 0·thinking off·출력 128토큰·
batch 1도 그대로다. 양성의 정답이 원문 구간에 남았는지 별도로 집계한다.

36문항 × 4조건 × 3반복 × 2모델 = **864회**, 모델별 432회다. Gemma 12B 다음
Qwen 27B를 실행한다. 반복은 독립 문항을 늘리지 않는다. 양성 EM, 유형별 성능,
올바른 null, helpful/harmful flip, pack 주입 문항 수, 실제 토큰·지연·반복 일치율을
측정한다. 정답과 oracle 구간은 pack이나 모델 입력에 전달하지 않는다.

전체 테스트, 실제 두 tokenizer/chat template의 용량, vLLM의 짧은 IPC 경로 bind를
검증한 후 큐를 실행한다. `sample_design`을 계획·준비 증빙·요청 프로토콜에 동일하게
봉인하고 실제 질문·parent·본문 해시의 고유 개수까지 확인한다. 자원이 부족하면
기다리며 다른 작업을 종료하지 않는다. 완료 뒤 원본을 비공개로 수집하고 재채점·
해시 검증을 통과한 집계만 자동 커밋·푸시한다.

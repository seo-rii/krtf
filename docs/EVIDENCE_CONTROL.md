# 동일 후보와 서버 근거 ID 진단 실험

2026-10-21. [확인 실험 2,304회](../reports/confirmation_queue_20261020/RESULTS.md)는
완료했다. 아래는 그 결과를 보고 선택한 후속 진단으로, 새 독립 검증이 아니다.
GPU 결과는 `reports/evidence_queue_20261021/`에서 별도로 게시한다. 현재는 준비 단계다.

## 질문과 자료

완료 실험에서 근거 인용문은 원문에 존재하지만 모델이 반환한 문자 위치가 틀리는
경우가 많았다. 또한 정답 후보가 검색됐어도 automation pack이 모호한 후보의
정의를 제공하지 않아 의미를 판단할 기회가 사라졌다. 원래 단순 용어표와 KTRF는
제공 후보와 승인 검증기가 달라, 그 결과만으로 표현 형식의 효과를 분리할 수 없었다.

원래 개발 자료 8개 family의 64문서만 사용한다. 이미 모델 출력과 집계를 확인한
자료이며 `EXPOSED_DIAGNOSTIC`으로 표시한다. 정답·문서·대상 위치·family를
변경하지 않고 원래의 source/review 해시를 보존한다. 확인 자료 128문서는 이 큐에
넣지 않는다. 사람 gold, 실제 업무 분포, 새로운 holdout 성능으로 해석하지 않는다.

## 네 조건

| 조건 | 의미 판단 입력과 근거 반환 |
|---|---|
| `plain_matched` | 실제 검색 후보를 단순 용어표로 제공, 간결한 ID 제안 |
| `ktrf_matched` | 같은 후보·사실을 구조화해 제공, 간결한 ID 제안 |
| `ktrf_evidence_ids` | 같은 후보와 근거 목록, 서버가 발급한 근거 ID를 반환 |
| `ktrf_evidence_offsets` | 같은 후보와 근거 목록, 인용문·문자 위치를 직접 반환 |

모든 조건의 후보는 실제 resolver 결과에서 가져오며 정답을 삽입하지 않는다.
같은 대상에 대해 후보 ID·정의·applicability를 동일하게 유지한다. 모호한 후보도
판단 입력에 포함하지만, 네 조건 모두 같은 production `occurrence_v1` 검증기를
통과해야 실행 가능한 선택이 된다. 모델 제안이 맞아도 기존 resolver가 확정하지
않은 연결은 승인되지 않는다. 후보 노출이 의미 판단에 주는 이득과 실행 승인에
미치는 효과를 별도로 보고한다.

두 근거 조건은 동일한 원문 근거와 속성 정보를 사용한다. 근거 목록은 원문·요청
위치·사전의 속성에서 생성하고 정답 라벨을 참조하지 않는다. 근거 ID는 요청의
문서·발생 위치에 결합되며, 서버가 원래 원문 구간과 속성 위치로 복원한다.
인용 일치, 대상 위치, 동일 표기의 다른 발생, 국가·시점·종류·범위 조건의 검사는
위치 복원 뒤에도 유지한다. 이는 문자열·위치 일관성 검사이며 의미 함의의 보장은
아니다. 잘못된 근거나 충분하지 않은 긍정 근거를 자동 승인할 권한도 만들지 않는다.

## 실행과 해석

Gemma 12B → Qwen 27B, 모델별 64×4=256회, **총 512회**다. temperature 0,
seed 0, thinking off, 단일 생성, JSON schema, 공통 출력 상한 768 tokens를
적용한다. 원문·정의를 자르지 않고 실제 두 tokenizer로 입력과 예약 출력의 합이
8,192 tokens 이내인지 검사한다. 다른 GPU 작업이 끝난 뒤 모델을 순서대로 올린다.

사전 고정할 비교는 단순 용어표 대 구조화, 기존 구조화 대 근거 검사,
문자 위치 직접 반환 대 근거 ID 반환이다. 주요 지표는 다음과 같다.

- 실행 검증 전 올바른 ID 제안·잘못된 ID 제안·기권.
- 같은 실행 검증기를 통과한 올바른 승인·오승인·거절된 정답.
- 응답 형식, 요청 참조, 근거 위치, 속성 대조의 실패 사유.
- 입력·출력 토큰, 모델 요청 지연, 서버 검증 시간.

원시 응답은 비공개로 보존하고 고정된 소스·요청·응답 해시로 재채점한 집계를
게시한다. family 단위 비교도 8개 군집의 기술 통계이며 운영 오류 보장이 아니다.
이번 결과를 보고 변경한 방법은 다른 새 자료에서 다시 확인해야 한다.

## 운영 연결과 남은 입력

[간결한 실행 API](COMPACT_EXECUTION.md)는 별도의 라이브러리 인터페이스다.
실험의 deterministic ID와 달리 운영 요청은 임의 참조·만료·한 번 소비를 사용한다.
이번 모델 결과를 그 API의 부하 또는 분산 운영 검증으로 바꾸어 해석하지 않는다.
실제 업무 shadow 평가는 문서·용어집이 제공되기 전까지 `WAITING_FOR_INPUT`이다.

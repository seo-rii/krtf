# HF TyDiQA 생성 비교: Qwen 27B 결과

Qwen3.5 27B의 768회 호출이 완료됐다. **이 표본에서는 전체 문서를 제공한 조건의
답변 정확도가 가장 높았고, KTRF의 일반 검색 대비 일관된 우위는 확인되지 않았다.**
Gemma4 12B는 서버 시작 중 GPU 여유 메모리가 줄어 실패했으며, 답변을 생성하지
않았다. 따라서 아래는 Qwen 한 모델의 결과이고 12B/27B 비교는 아직 없다.

고정 입력은 한국어 질문 128개·서로 다른 원문 기사 128개다. SPAN 56개와 YES/NO
8개가 답변 가능 양성이며, 기사에 답이 없다는 주석이 일치하는 64개는 별도로
집계한다. 여섯 조건 각각 128회, 누락·API 오류는 0건, 형식 오류는 총 9건이다.
실행은 2026-10-16 23:11 KST에 종료됐다. 추론 코드 revision은 `cfdd5c5`다.

## 답변 정확도와 비용

| 조건 | 답변 가능 EM | 기사 무응답의 올바른 null | 형식 오류 | 평균 입력 토큰 | p95 지연 |
|---|---:|---:|---:|---:|---:|
| 문맥 없음, 자체 지식 허용 (`none_knowledge`) | 24/64 (37.50%) | 미채점 | 2 | 109.2 | 1.78초 |
| 문맥 없음, 근거 전용 (`none_evidence`) | 0/64 (0.00%) | 64/64 | 0 | 165.2 | 0.55초 |
| 전체 문서 (`full`) | 45/64 (70.31%) | 56/64 | 3 | 3,293.8 | 3.34초 |
| 검색 문맥 (`retrieved`) | 31/64 (48.44%) | 63/64 | 0 | 484.1 | 1.43초 |
| KTRF 검색어 확장 (`ktrf_expanded`) | 31/64 (48.44%) | 63/64 | 0 | 484.2 | 1.43초 |
| 검색 문맥 + KTRF pack (`ktrf_pack`) | 33/64 (51.56%) | 59/64 | 4 | 633.5 | 1.42초 |

EM은 NFC·casefold·공백 정리 후 원천 정답 중 하나와 완전히 일치하는 비율이다.
공식 TyDi byte-span 점수가 아니다. 평균 입력 토큰과 지연은 양성·음성을 포함한
각 조건의 전체 128회 기준이다. 공유 서버의 지연은 관측값이며 인과적 속도 비교나
운영 지연 보장으로 해석하지 않는다. `none_evidence`의 null 일치는 답변 능력보다
정보 없이 기권하라는 정책을 지킨 결과다.

## KTRF 유무의 차이

검색어 확장은 128질문 중 3개에서 일어났고, 일반 검색 대비 정답·오답의 전환은
0건이었다. KTRF pack은 28질문에 실제 주입됐다. 주입되지 않은 100질문은 검색
조건과 결과가 같았다.

Pack의 추가 정답 2건은 모두 YES/NO였다. SPAN은 검색과 pack 모두 27/56으로
같았으며, YES/NO는 4/8에서 6/8로 늘었다. 양성 EM의 증가는 **2/64, 3.125%p**지만,
동시에 기사 무응답 4건에서 형식 오류가 발생했다. 검색에서는 이 4건을 올바른
null로 처리했다. Pack 입력 토큰은 검색 대비 30.9% 증가했다.

공식 집계의 paired 값은 pack helpful 2, harmful 0, 불완전 쌍 4다. 형식 오류 4건은
paired 계산에서 제외하므로 **harmful 0을 악화가 없다는 의미로 읽으면 안 된다.**
작은 YES/NO 하위 표본의 개선만으로 KTRF 전반의 우위를 주장할 수 없다.

전체 문서는 검색보다 양성 정답을 14개 더 맞혔다. 유효 응답끼리의 비교에서는
SPAN helpful 16·harmful 2, 기사 무응답 harmful 4이며 형식 오류 쌍 3개가 별도다.
정보를 더 주는 조건이므로 검색과 같은 입력 비용의 비교는 아니다. 검색은 입력
토큰을 85.3% 줄였지만, 정답 근거가 선택 구간에 보존된 양성은 41/64로 줄었다.
검색·pack의 정답 중 각각 2건은 해당 선택 구간에 gold 근거가 없는 상태에서
나왔다. 답변 EM과 근거 보존을 합치지 않는다.

## 검증과 남은 작업

수집 시 원본 요청·응답·채점 파일의 SHA-256, manifest seal, 고정 요청 identity,
실행 환경을 확인했다. 로컬에서 모든 문항을 다시 채점해 정답·기권·형식 오류와
개별 F1이 일치함을 확인했다. Python 3.11/3.12의 부동소수점 합산 차이는 F1 합계에만
최대 2 ULP를 허용하며 봉인된 합계를 유지한다. 지연 합계에는 `math.fsum`을 사용한다.
원문·개별 답변·원본 로그는 공개하지 않는다.

Gemma는 [별도 고정 계획](GEMMA_RETRY_PLAN.json)에 따라 같은 입력으로 다시 실행하고
Qwen 결과는 해시로 검증해 재사용한다. 실행기를 포함한 one-server 테스트는
1,375개 통과했다. 계획의 `status_path`가 실제 재실행 상태를 기록하며, 이 준비
기록 자체가 Gemma 완료를 의미하지 않는다.
시작 전 명시적인 GPU 여유 메모리 오류만 최대 3회 재시도하고, 이미 생성된 답변은
재시도하지 않는다. 이 복구는 질문·채점·모델 설정을 바꾸지 않는다.

이번 표본은 두 모델의 8,192토큰 용량에 공통으로 들어가는 문서만 골랐고, 양성·음성
비율을 균형화했다. 전체 한국어 TyDiQA 분포나 실제 서비스에 대한 정확도·위험
보장이 아니다. Wikipedia와 모델 사전학습 중복도 배제하지 못한다. Pack에는 형식과
정책이 함께 들어가므로, 단독 포맷 효과로 해석하지 않는다.

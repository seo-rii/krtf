# 후속 실험 고정 계획

후속 실행은 완료됐다. 현재 결과는 [최종 분석](followup_queue_20261018/ANALYSIS.md)과
[종료 상태](followup_queue_20261018/RESULTS.md)를 참조한다. 아래 준비 기록은 그대로 보존한다.

**생성 전에 동결한 계획이다. GPU 완료 여부는 아래 큐 상태에서 확인한다.**
추론·실행기 revision `492120c`의 one-server 전체 테스트는 **1,502개 통과**했고,
고정 source archive와 요청·CPU 증빙을 검증하는 오프라인 큐 사전검사도 통과했다.

| 작업 | 표본과 조건 | 실행량 |
|---|---|---:|
| 독립 기사 검색 | 새 기사 128개 × lexical/BM25/인접 구간/oracle × 두 모델 | 1,024회 |
| JSON 강제 생성·반복 | 기존 128질문 × 검색/pack × 자유/스키마 × 3회 × 두 모델 | 3,072회 |
| 독립 AI 문단 gold | 실제 문단 24개, 사전 고정·출력 비공개 주석 2회·조정·봉인 후 fast/commit | CPU 평가 완료 |

Gemma 12B에서 검색→반복, Qwen 27B에서 검색→반복 순서로 모델별 runtime 하나를
재사용한다. 총 GPU 요청은 **4,096회**다. 두 실제 chat template에서 최대 입력은
검색 Gemma/Qwen 1,637/1,513토큰, 반복 2,142/1,946토큰으로, 출력 128토큰을 더해도
8,192토큰 한도에 들어간다. JSON 요청 모델과 xgrammar 문법 컴파일의 CPU 사전검사도
통과했다. 서버의 실제 생성 성공은 이후 결과로 판단한다.

## 먼저 완료한 CPU 진단

새 검색 표본은 이전 생성·준비 pool·근거 평가·blind 문단의 기사 parent 및 내용
해시를 제외했다. 최초 구성의 고유 기사 수가 부족해 실패 inventory를 보존하고
생성 전에 SPAN 40·YES/NO 8·무응답 80으로 변경했다. 양성은 48개이며 이전
생성 평가의 양성 64개와 분모가 다르다. 모든 검색기를 그대로 GPU 비교에 넣는다.

| 검색 조건 | 새 표본의 양성 근거 보존 |
|---|---:|
| lexical | 33/48 (68.75%) |
| BM25 | 35/48 (72.92%) |
| 인접 구간 | 22/48 (45.83%) |
| oracle | 48/48 (100%, gold를 쓴 진단 조건) |

이는 LLM 답변 정확도가 아니다. 공통 예산은 두 모델 각각 원문 최대 1,536토큰,
3,000문자·3구간이며 실제 소비 토큰이 같지는 않다. Oracle은 정답 문단을 알고
있는 조건으로, 배포 가능한 검색 방법이나 공정한 검색 순위에 포함하지 않는다.

문단 gold는 LINK 4개·NIL 46개, 무언급 문단 14개다. fast/commit 모두 등록 연결
4건을 맞혔고 NIL 오확정은 없었다. 그러나 test 8문단의 LINK는 2개뿐이고 보정
8문단의 LINK는 0개다. 보정 학습을 하지 않고 **INSUFFICIENT_DATA**로 남겼다.
AI 주석이며 원문 문단만 평가했으므로 운영 오류율·전체 기사 탐지·파생 의미 guard에
대한 보장으로 해석하지 않는다.

## 실행 증빙과 결과 위치

큐 PID와 수집기 PID는 private launch receipt에 기록한다. 공개 계획은 실행 상태를
자동으로 갱신하는 파일이 아니다.

```sh
ssh one-server 'cat /home/one/logs/ktrf-followup-20261017T173119Z/queue.status.json'
ssh one-server 'tail -n 30 /home/one/logs/ktrf-followup-20261017T173119Z/queue.log'
```

검증된 결과는 `reports/followup_queue_20261018/`에 게시한다. 수집기는 원본
요청·응답·채점 파일의 해시와 manifest seal을 확인해 다시 채점한 뒤 집계만
커밋·푸시한다. 반복은 질문 수를 늘리는 독립 표본으로 세지 않는다. 오류·형식
불량을 올바른 null로 보상하지 않는다. raw 원문·개별 답변은 공개하지 않는다.

# HF TyDiQA 생성 비교 최종 결과

Gemma4 12B와 Qwen3.5 27B가 동일한 질문 128개·여섯 조건의 **총 1,536회 호출을
완료했다.** 두 모델 모두 누락·API 오류는 0건이다. 형식 오류는 Gemma 2건,
Qwen 9건이며 해당 문항은 정답이나 올바른 기권으로 보상하지 않았다.
Gemma 실행은 2026-10-17 00:41:48 KST에, 자동 재채점·게시는 00:42:37 KST에
성공 종료했다. Qwen은 앞서 완료한 봉인된 결과를 재사용했고 다시 생성하지 않았다.

**이 표본에서는 두 모델 모두 전체 문서 조건의 답변 정답률이 가장 높았다.
검색 문맥에서 KTRF pack의 추가 이득은 작고, Qwen에서는 기권 문항의 형식 오류
비용이 발생했다. 27B가 모든 조건에서 더 좋은 결과도 아니었다.**

## 답변 가능한 질문의 정확도

분모는 SPAN 56개·YES/NO 8개, 총 64개다. 기사에 답이 없는 64개는 다음 표에서
별도로 다룬다. EM은 NFC·casefold·공백 정리 후 원천 정답 중 하나와 완전히
일치한 비율이며, 공식 TyDi byte-span 점수가 아니다.

| 조건 | Gemma 12B | Qwen 27B |
|---|---:|---:|
| 문맥 없음, 자체 지식 허용 (`none_knowledge`) | 18/64 (28.1%) | 24/64 (37.5%) |
| 문맥 없음, 근거 전용 (`none_evidence`) | 0/64 (0.0%) | 0/64 (0.0%) |
| 전체 문서 (`full`) | **43/64 (67.2%)** | **45/64 (70.3%)** |
| 검색 문맥 (`retrieved`) | 32/64 (50.0%) | 31/64 (48.4%) |
| KTRF 검색어 확장 (`ktrf_expanded`) | 32/64 (50.0%) | 31/64 (48.4%) |
| 검색 문맥 + KTRF pack (`ktrf_pack`) | 33/64 (51.6%) | 33/64 (51.6%) |

`none_evidence`는 원문 없이 원문에만 의존하라는 정책 대조군이다. 두 모델 모두
양성 64개에서도 기권했으므로, 0점은 일반적인 모델 지식 수준을 뜻하지 않는다.

## 기사 무응답과 형식 안정성

아래 null 분모는 세 원천 주석이 모두 기사에 답이 없다고 판단한 64개다. 형식
오류는 각 조건의 양성·음성을 포함한 128회 전체에서 센다. 자체 지식 조건의 기사
무응답은 세상에 답이 없다는 의미가 아니므로 채점하지 않는다.

| 조건 | 올바른 null: Gemma / Qwen | 형식 오류: Gemma / Qwen |
|---|---:|---:|
| 자체 지식 | 미채점 | 0 / 2 |
| 근거 없이 기권 정책 | 64 / 64 | 0 / 0 |
| 전체 문서 | 61 / 56 | 0 / 3 |
| 검색 문맥 | 61 / 63 | 0 / 0 |
| KTRF 검색어 확장 | 61 / 63 | 1 / 0 |
| 검색 + KTRF pack | 62 / 59 | 1 / 4 |

Gemma의 pack은 검색 대비 양성 정답 1건과 올바른 null 1건이 늘었다. 유효한
쌍에서의 추가 정답은 SPAN 1건·무응답 1건이며, 형식 오류 쌍 1개는 별도다.
Gemma의 확장·pack 형식 오류는 각각 해당 추가 정보가 적용되지 않은 SPAN에서
발생했다. 이때 검색 대조군과 실제 `system`·`user`가 같았다. 따라서 모든 차이를
KTRF 개입 효과로 단정할 수 없으며, 온도 0의 단회 실행도 반복 일치를 보장하지 않는다.

Qwen pack의 추가 양성 정답 2건은 모두 YES/NO이고 SPAN은 같았다. 반면 검색에서
올바르게 null을 반환한 무응답 4건이 pack에서 형식 오류가 됐다. 집계의
`helpful=2, harmful=0`은 그 4쌍을 제외하므로 **악화가 없었다는 뜻이 아니다.**
두 모델에서 pack이 항상 유리하다는 결과는 아니다.

## 검색·토큰 비용과 모델 크기

검색 구간에 gold 근거가 남은 양성은 두 모델 공통 41/64이며, 전체 문서는
64/64다. 제한된 검색 구간에서 Gemma 정답 1건, Qwen 정답 2건은 gold 근거가
없는 상태에서 나왔다. 답변 정답과 근거 보존을 혼동하지 않는다.

질문 확장은 128개 중 3개, pack 주입은 28개에만 적용됐다. 확장은 양성 정답 수를
늘리지 못했다. Pack 입력 토큰은 일반 검색 대비 두 모델 모두 약 30% 늘었다.
일반 검색은 전체 문서 대비 입력 토큰을 약 85% 줄였다.

| 조건 | 입력 토큰 합: Gemma / Qwen | p95 지연: Gemma / Qwen |
|---|---:|---:|
| 전체 문서 | 455,143 / 421,603 | 1.71초 / 3.34초 |
| 검색 문맥 | 67,197 / 61,963 | 0.90초 / 1.43초 |
| 검색 + KTRF pack | 87,606 / 81,088 | 0.91초 / 1.42초 |

토큰·지연은 각 조건의 128회 전체 기준이다. 토크나이저와 모델 계열이 다르고,
공유 서버에서 서로 다른 시점에 실행했으므로 지연을 통제된 크기 효과로 읽지
않는다. Qwen은 자체 지식·전체 문서 양성 EM에서 높았지만, 검색에서는 Gemma가
1개 높고 pack은 동률이었다. 큰 모델의 일괄 도입을 뒷받침하는 결과는 아니다.

## 검증·해석 범위

두 모델은 같은 요청 corpus·온도 0·seed 0·thinking off·출력 128토큰을 사용했다.
추론 코드는 `cfdd5c5`, 복구 실행기는 `a9aae94`이며, 실행기를 포함한 one-server
테스트는 1,375개 통과했다. 복구 첫 시도도 GPU 메모리 부족으로 종료됐으나 두 번째
시도에서 정상 시작했다. 응답을 생성한 이후의 질문·답변 재시도는 없었다.

공개된 결과는 원본 요청·응답·채점의 SHA-256, manifest seal, 원본·재실행 환경과
provenance를 확인한 뒤 로컬 재채점했다. 최종 확인에서도 문항별 점수와 공개 집계,
동일 질문의 모델 비교가 일치했다. 원문·개별 답변·로그 원문은 공개하지 않는다.
Gemma의 upstream checkpoint revision은 확인되지 않았다는 상태를 그대로 보존한다.

이 표본은 두 모델의 8,192토큰 용량에 들어가는 서로 다른 128기사를 양성·음성
균형으로 골랐다. 한국어 TyDiQA 전체 분포나 실제 서비스의 정확도·위험 보장을
대표하지 않는다. Wikipedia·모델 사전학습 중복을 배제하지 못하며, pack에는 형식과
정책이 함께 들어간다. 작은 개선을 일반적인 검색 우위나 운영 안전성으로 확대하지 않는다.

다음 개선의 우선순위는 정답 근거를 더 잘 회수하는 검색과 출력 형식 안정성이다.
이 실험에서는 전체 문서를 넣을 수 있을 때 양성 정답률이 가장 높았고, 비용을
줄이기 위해 문맥을 제한하면 검색 단계의 근거 손실이 남았다.

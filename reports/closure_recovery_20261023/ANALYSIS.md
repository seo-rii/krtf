# 근거 연결·기권 형식·긴 문서: 최종 960회 분석

새 96문서·12 family에 대한 5조건 비교를 두 모델에서 모두 완료했다. Gemma 480회와 Qwen 480회, 총 960개 관측이며, 추론·원시 응답 재채점·보고서 수집·게시가 모두 exit 0이다. 완료 시각은 2026-10-23 09:57 KST이다.

Qwen의 `closure_bundle`이 이번 평가에서 가장 유망했다. 정상 shadow 연결 46/48건과 음성의 유효 기권 48/48건을 유지하며 p95 7.04초였다. Gemma는 null 전용 분기에서 정상 연결이 0건으로 무너졌다. 같은 출력 형식을 모든 모델에 적용할 근거는 없다.

## 조건별 결과

각 조건은 연결 대상 48문서와 음성 48문서다. 정상 연결과 오승인은 **실행 권한이 없는 실험용 shadow 판정**이다. 형식 오류는 실패로 남겼으며 재시도하지 않았다.

Gemma의 새 null 형식 세 조건에서 양성 48건은 각각 유효한 null 29/28/43건과 형식 오류 19/20/5건으로 나뉜다. 형식 오류 44건 전부 양성이며, 출력 상한 768토큰에 도달한 `finish_reason=length`였다. API 오류와 누락은 두 모델 모두 0이다. 스키마 컴파일 통과만으로 실제 생성이 끝까지 유효한 JSON을 만들거나 올바른 분기를 고른다고 보장할 수 없다. 구체적인 모델·grammar 상호작용의 원인은 이번 실험에서 분리하지 않았다.

LINK의 정상 연결과 음성의 유효 기권을 합친 `correct`만으로 설정을 고르면 안 된다. Gemma의 `closure_legacy`→`closure_null`은 그 합계가 31→48건으로 늘지만, 정상 연결은 31→0건으로 사라진다. 두 모집단의 성과와 실패를 따로 유지한다.

기존 형식에서도 기권 표현에 문제가 있다. Gemma는 `manual_legacy`/`closure_legacy`에서 null을 41/43건 제안했지만 assertion·근거 필드가 일관되지 않아 유효 기권은 0건이었다. Qwen의 `manual_legacy`도 null 제안 47건이 같은 종류의 검사에 걸렸다. 유효 기권 0건을 기권 의도가 0건인 것으로 읽으면 안 된다.

## 개선 효과와 확인되지 않은 효과

Qwen의 `closure_null`→`closure_bundle`은 정상 연결 46건을 유지하면서 출력 토큰 8,802→4,583개(47.9% 감소), p95 15.104→7.037초(53.4% 감소)였다. 전체 토큰은 361,036→358,435개로 0.72% 줄었고 입력 토큰은 0.46% 늘었다. 출력 비용 절감과 전체 입력 비용 절감을 구분해야 한다.

Gemma의 `manual_legacy`→`closure_legacy`는 정상 연결 1→31건으로 늘었다. 그러나 **두 모델의 모든 조건에서 서버 추가 segment가 0건이고 raw/closed 판정이 같다.** 이번 결과는 서버가 실제 누락 근거를 보충해 회복한 효과를 입증하지 못한다. 조건별 정책 문구와 출력 형식이 바뀌면서 모델이 선택한 근거가 달라진 효과까지 포함한다. 기존 CPU 사후 재분석의 45/47건 회복과 합산하지 않는다.

Qwen의 묶음 조건은 짧은 문서·긴 문서 각각 정상 23/24건, 음성 기권 24/24건이었다. Gemma의 가장 높은 정상 연결 조건인 `closure_legacy`는 짧은 문서 22/24건, 긴 문서 9/24건으로 차이가 컸다. Gemma의 null 형식 실패는 짧은 문서에서도 발생했으므로 입력 길이 초과만으로 설명하지 않는다. 원문·정의는 자르지 않았고 실제 입력 토큰 한도를 사전 검증했다.

## 운영 계약과 자료의 한계

Qwen의 생산 guard 정상 연결은 모든 조건에서 35/48건이다. `manual_legacy`의 생산 guard 오승인 1건은 strict shadow에서 차단됐다. Gemma의 기존 두 형식은 생산 guard 정상 연결 35/48건, 오승인 7/5건이며 strict shadow는 오승인을 모두 차단했다. 실험용 shadow 46/48건이나 오승인 0건을 운영 검증기의 성능 또는 배포 위험 보장으로 표시하지 않는다.

두 모델 모두 대상 96건의 exact-core 탐지와 LINK 48건의 정답 후보 회수는 전부 성공했다. 따라서 이번 셋에서는 탐지·검색 누락이 결과를 제한하지 않았다. 여덟 과제 구조를 반복하는 AI 작성·AI 검토 문서이며, 사람 gold나 실제 업무 분포를 대표하지 않는다. 독립 문서가 960개인 것도 아니다. 문서·family를 유지한 paired 결과와 길이별 결과를 함께 읽어야 한다.

사전 A/B 역할별 국내외·절차/시스템과 공유 약칭 LINK 정답은 균형을 맞췄지만, 고유 명칭의 explicit/implicit LINK는 A, 문단 간 LINK는 B에 치우친 상관이 남는다. 공개 요약의 주요 하위 집계는 길이와 family다.

## 복구와 재현

원래 큐에서 Gemma는 KV 캐시 확보 실패로 benchmark 시작 전에 종료했다. 복구는 GPU 메모리 예약만 0.45→0.75로 높여 Gemma 480회를 생성했다. Qwen은 원래 480개 응답·실행 환경·manifest를 바이트 그대로 검증·재채점해 재사용했으며 재생성하지 않았다. 추론·채점 코드 `79cb203`, 복구 코드 `d819eaa`와 테스트 증거를 분리했다. 복구 코드 one-server 전체 테스트는 2,495개 통과, 11개 건너뜀이다.

원시 응답은 비공개로 보존하며 아래 집계 파일은 해당 봉인 자료의 재채점 결과다. 모델 실행 시점과 메모리 예약이 달라 모델 간 지연은 공유 서버에서의 관측값으로 해석한다.
